# Shared Infrastructure

## Package Contracts And Application Setup

- Native ESM package contract.
- Stable shared names and UI config defaults.
- Application UI manifest template.
- Application Entry Point template and setup lifecycle helper.
- Required/optional service and Core UI context validation.
- Idempotent synchronous shutdown ownership.

## `PeyElement`

- `PeyElement` shared custom-element base class with mandatory open Shadow DOM.
- Connect-once lifecycle with the fixed `{ infrastructure, refs }` envelope; the base class owns the final `connect` method and delivers only component refs to `onConnect(refs)`.
- Declarative Event Bus subscriptions (`subscriptions()`) and a controlled `publishUIEvent()` publisher, both private to the base class; subscription and unsubscribe-return shapes are validated.
- Delegated DOM listeners from `eventTypes()`, registered once and cleaned up on disconnect; `handleEvent()` runs inside the error boundary.
- Coalesced microtask rendering where a single `preserve: false` request dominates the cycle; a render cycle executes only while the element is connected at flush time.
- Transactional subscribe/bind: a `connectedCallback` failure rolls back every subscription and listener registered so far, and per-entry cleanup never lets one throwing `unsubscribe()`/`removeEventListener` block the others.
- Render boundary with a structural (text-free) fallback, `ui:component-error` publication, and a sanitized optional logger payload.
- Declarative preserve mechanism (`data-pey-preserve` / `data-pey-preserve-state`) for value, checked, selection, focus, and scroll across full re-renders, restoring only the old/new token intersection and reconciling radio groups by `name` and form owner.

## Shared State

- `createSharedState()` at the package root: a frozen, UI-local store exposing `get(key)`, `set(key, value)`, `subscribe(key, listener)`, and `clear()`.
- Value validation to strict JSON-compatible data only (plain JSON whose nested items are likewise strict, so `undefined` is rejected rather than coerced), with cycle detection and a depth limit of exactly 100 array/object containers (the 101st container is rejected); empty, whitespace-only, or untrimmed keys and non-function listeners are rejected with stable `PEY_SHARED_STATE_*` codes.
- `Object.is` equality semantics: an equal value triggers no notification, and a new object or array always notifies even with identical content.
- No cloning or freezing of stored values; immutable replacement with a new reference is a documented consumer contract.
- Per-key subscriptions with idempotent unsubscribe (re-subscribing the same listener registers once), listener isolation (a throwing listener logs only the stable `PEY_SHARED_STATE_LISTENER_FAILED` code and never blocks the others), and a previously issued unsubscribe staying a safe no-op after cleanup.
- `clear()` is a deliberate extension of the fixed `get`/`set`/`subscribe` API so the Entry Point can deterministically release listeners and values on shutdown.

## Shell, Styling, Tokens, And Assets

- `AppShell` at `shell/app-shell.js`: a neutral, product-free top-level component extending `PeyElement`. It defines the slot/host contract through named slots (`extension`, `page`, `extension-end`) and a semantic `<main>` page landmark, without imposing product layout or redirecting focus.
- `AppShell` connection is transactional: if shared-state connection fails after the base lifecycle was established, the failure path deliberately runs the cleanup hooks early — rolling back the base subscriptions/listeners via `disconnectedCallback` semantics before the error is surfaced. Cleanup therefore runs once for the failed connection and may run again later if the browser later removes the element; all shell and base cleanup is idempotent (empty arrays and safe no-op unsubscribes), so early rollback never causes double-unsubscribe or double-listener-removal issues.
- Base presentation states (`theme`, `direction`) are reflected onto the shell host as `data-theme` / `dir` attributes, seeded from connection refs and kept in sync with the UI-local shared state store.
- `tokens.css`: minimal design tokens as CSS Custom Properties on `:root`, consumed through `var(--pey-*)` across the Shadow DOM boundary; values are overridable from a consuming application's config/theme.
- `base/attach-style-sheet.js`: the final runtime for a separate stylesheet (`getStyleText`, `getCachedStyleText`, `applyStyleSheet`, `attachStyleSheet`, `STYLESHEET_ATTRIBUTE`). The mechanism is preload-and-cache-`<style>`: the sheet is preloaded once, its text is inlined as a `<style>` inside the Shadow DOM before the styled content mounts, only the successful text is cached by href, concurrent callers share one in-flight load, a failed load is evicted so a later call can retry, and the preload `<link>` is removed once loaded. `PeyElement` integrates it through the `stylesheetHref()`/`stylesheetNonce()` hooks: the first contentful render waits for the sheet, every full render re-applies the cached text without re-fetching, the nonce is re-read on each render and validated on apply, and a load failure (`PEY_ELEMENT_STYLESHEET_FAILED`) stays sticky for that href until `retryStylesheet()` clears it while the component still renders without the sheet. Inline `<style>` inside `render()` remains the default for small components; a component opts into the external sheet by overriding `stylesheetHref()`.
- `base/icon-sprite.js`: the `<svg><use>` sprite contract. `resolveIconSpriteUrl()` derives the sprite URL exclusively from `assetBaseUrl`; `createIconMarkup()` produces the documented decorative `<svg aria-hidden="true" focusable="false">` markup.
- `assets/icons.svg` sprite file prepared; `assets/fonts` and `assets/images` paths exist without product assets.

## Page Loading And Routing

- `routing/page-loader.js`: `createPageLoaderRegistry()` validates the Entry Point's route catalog (non-empty trimmed `pattern`, `load()` function, a valid trimmed kebab-case custom-element `element` tag, optional `connect()` override, optional `notFound` slot without a pattern, no duplicates) and returns a frozen lookup registry with `getEntry(pattern)` and `notFoundEntry`. Loader validation failures use the `startup` error type, since the catalog is validated at startup. `defaultConnect(element, infrastructure, refs, route)` builds the standard page connection envelope, merging `routeParams`/`routeQuery` into the base refs.
- `routing/page-host.js`: `createPageHost()` mounts pages into the application shell. It subscribes to `router:changed`, reads the full route with `getCurrentRoute()`, and mounts/unmounts pages, guarding every async step with a generation counter so a stale slow load never overrides a newer route. The `router:changed` callback is contained: a throwing `getCurrentRoute()` is logged as `PEY_PAGE_ROUTE_READ_FAILED`, while any failure in the mount flow — a synchronous invocation error or an asynchronous rejection — is logged as `PEY_PAGE_ROUTE_MOUNT_FAILED`; neither ever escapes the Event Bus listener. The router subscription is validated at construction (`PEY_PAGE_HOST_SUBSCRIBE_INVALID` on a throwing or non-unsubscribe-returning subscribe). `dispose()` is terminal: it bumps the generation counter (invalidating in-flight loads), unsubscribes, and unmounts the current page inside a `finally` block; a throwing `unsubscribe()` is contained and logged as `PEY_PAGE_UNSUBSCRIBE_FAILED`, so `dispose()` never throws while still guaranteeing the page is removed. It never registers routes and never owns a `/not-found` route: resolving unresolved paths is the Router's own job (its `notFoundPath`), so the host only covers not-found and load-failure states. `config.fallbackPath` is only the safe-path action the fallback offers.
- Fallback policy: a valid route whose loader or connect fails renders the `pey-page-fallback` load-failed state with retry; retry reuses the normal `mountForRoute()` flow rather than a distinct mounting path, and the retry callback returns the mount promise so the fallback can contain its rejection. A route with no loader is a config error and renders load-failed without retry; an unresolved not-found route renders the not-found state (via the optional notFound slot when defined) without retry. A failure while building, connecting, or appending the fallback itself is contained and logged with the stable `PEY_PAGE_FALLBACK_MOUNT_FAILED` code, so the mount flow never rejects as a side effect of a broken fallback — the host may still be left empty, but only because there is no renderable output left to show.
- `routing/page-fallback.js`: internal `pey-page-fallback` element (`PageFallback`, `PAGE_FALLBACK_STATES`). It renders only stable message keys — never technical error text — with optional retry, go-back, and go-to-fallback actions; translated output is HTML-escaped before insertion, and go-back/go-to-fallback render only when the router (and path) actually exist. Technical causes are logged with stable codes (`PEY_PAGE_LOAD_FAILED`, `PEY_PAGE_MOUNT_FAILED`, `PEY_PAGE_LOADER_NO_ENTRY`, `PEY_PAGE_ROUTE_READ_FAILED`, `PEY_PAGE_ROUTE_MOUNT_FAILED`, `PEY_PAGE_UNSUBSCRIBE_FAILED`, `PEY_PAGE_FALLBACK_MOUNT_FAILED`, `PEY_PAGE_FALLBACK_NAVIGATION_FAILED`, `PEY_PAGE_FALLBACK_RETRY_FAILED`) through the console only, never a raw `error.message`.

## I18n And Formatting

- `i18n/catalog.js`: kit-owned internal translation catalog (`KIT_TRANSLATIONS`, default language `en`). It carries exactly the infrastructure keys the kit renders — `pey.webui.errors.page-not-found`, `pey.webui.errors.page-load-failed`, `pey.webui.actions.retry`, `pey.webui.actions.go-back`, `pey.webui.actions.go-to-fallback` — and no product keys. Applications translate these keys in their own catalogs when needed.
- `i18n/create-i18n.js`: `createI18n({ language, fallbackLanguage, catalog })` returns a frozen `{ t, format, language }`. The Entry Point builds one instance with the application catalog and injects `t`/`format` as refs; components never import the kit's i18n directly and the kit never imports a product catalog. Languages are validated structurally via `Intl.getCanonicalLocales()` — the active/fallback tags and every catalog language key. `t(key, params)` requires a non-empty trimmed string key (any other input returns an empty string) and resolves active language → fallback language → kit `en` catalog → the key itself, with the whole lookup plus interpolation contained so it never throws and never surfaces a raw error; it returns raw, unescaped text and the caller is responsible for HTML-escaping it. `format(value, type, options)` renders `date`/`time`/`dateTime`/`number`/`currency` via `Intl` for the active language (a `locale` option is stripped and not honored; `dateTime` renders a date and a time by default; the currency style/code cannot be overridden), with structured `PEY_I18N_*` errors for invalid usage or non-plain-object options and any underlying `Intl` failure normalized into `PEY_I18N_FORMAT_FAILED`.
- Fallback wiring: the page host uses the kit `t` (built from `config.language`, or from the shared-state `language` key when a valid facade is provided) as the default for `pey-page-fallback` when the Entry Point injects no `t`, so not-found and load-failed outcomes render localized kit text rather than raw keys from the very first deploy. A language change in shared state re-renders an active fallback (rebuilding it before swapping so a failed rebuild keeps the existing fallback and translation); the shared-state path is best-effort and degrades to `config.language` on any failure.

Every runtime module added under `routing/` has a matching test path under `tests/routing/`; i18n modules are tested under `tests/i18n/`.
